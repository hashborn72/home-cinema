# Домашняя медиатека

Приложение для Android TV с собственными витринами, поиском, избранным и историей просмотра.

- **Jackett** получает раздачи LostFilm, ExKinoRay и RuTor.
- **TorrServer** передаёт видео через backend плееру, используя RAM-кэш.
- **Backend** собирает каталог, подключает Anwap, хранит медиатеку и позиции просмотра. TMDB — необязательный источник постеров и описаний.
- **Android-приложение** показывает каталог; воспроизведением занимается отдельно установленный **Just Player** или **VLC**.

## Развёртывание

На сервере нужны Git, Docker и Docker Compose. Порт backend не должен быть занят другим сервисом.

```sh
git clone https://github.com/hashborn72/home-cinema.git
cd home-cinema
docker compose up -d
```

По умолчанию используется адрес `192.168.1.144`. Для другого адреса скопируйте `.env.example` в `.env` и измените `CINEMA_HOST` до запуска.

- Backend и страница установки: `http://192.168.1.144:8093/install`
- Jackett (`jackett:9117`) и TorrServer (`torrserver:8090`) доступны только сервисам внутри Docker Compose. Их порты на хост не публикуются.

Приложение и выбранный плеер используют только порт backend. Видео передаётся по временной ссылке конкретного файла с поддержкой перемотки (HTTP Range), без сохранения медиапотока на диск.

Индексаторы преднастроены, но личные аккаунты LostFilm/ExKinoRay нужно перенести отдельно через каталог `private` до первого запуска. Ключ Jackett создаётся автоматически. Секреты не хранятся в Git; необязательный TMDB-токен можно положить в `private/tmdb-token` перед первым запуском.

## Телевизор

Установите подписанный APK и Just Player или VLC. APK распространяется отдельно; если положить его в `dist/home-cinema.apk`, он будет доступен на странице установки.

Выбор плеера: «Настройки» → «Выбор плеера и проверка подключения» → Just Player или VLC. По умолчанию используется Just Player. Выбор сохраняется на телевизоре и применяется к каталогу и тестовому ролику. Для сравнения изображения вернитесь в каталог и откройте тот же файл. Возвращайтесь кнопкой Back для передачи позиции просмотра; VLC не сообщает явную причину завершения, поэтому приложение не выставляет по его результату отметку «просмотрено» автоматически.

Откройте приложение, укажите сервер `http://192.168.1.144:8093` и нажмите «Подключить». Код и API-ключ вводить не нужно. Адрес сохраняется на телевизоре.

## Данные и обслуживание

Настройки и медиатека находятся в постоянных Docker-томах. Обычный `docker compose down` их сохраняет; **не используйте `down -v`, если данные нужны**.

```sh
docker compose ps
docker compose exec backend python manage.py backup
git pull
docker compose up -d
```

Команда backup сохраняет снимок SQLite внутри тома backend. Для защиты от потери сервера копируйте его и настройки сервисов на другое устройство отдельно.

## Проверка изменений

Для интеграционных проверок запускайте полный `compose.yaml` отдельным проектом, со своими томами и свободным `BACKEND_PORT`. Backend обращается к Jackett и TorrServer по именам сервисов внутри сети этого проекта. Старый `compose.dev.yaml` запускает только backend и больше не подходит для проверки торрентов: он рассчитывал на опубликованные порты production. Открывать их снова для разработки не нужно.

Android UI-тесты запускаются через `:app:testDebugUnitTest` и `:app:testReleaseUnitTest`. `TvLayoutTest` проверяет подписи, переключение сезонов, продолжение просмотра и фокус пульта на экране 960×540 dp; снимок отрисовки сохраняется в `app/build/reports/tv-layout`.

По умолчанию включён доверенный режим (`CINEMA_AUTH_MODE=trusted-lan`): любой, кто имеет сетевой доступ к backend, может пользоваться каталогом и менять общую медиатеку. Пароли трекеров остаются на сервере. Комплект предназначен только для доверенной домашней сети — не открывайте эти порты в интернет.

## Обновления Android TV (0.9.8+)

Сборка, тесты и подписание выполняются только на Autobot (`192.168.0.221`):

```sh
# Отредактировать versionCode/versionName в app/build.gradle.kts и release-notes.txt.
bash scripts/build-release.sh
```

Скрипт использует существующий ключ из `/root/.local/share/home-cinema-signing`.
После проверки подписи он извлекает версию и minSdk из APK, создаёт неизменяемый
`dist/home-cinema-<versionCode>-<sha256>.apk` и атомарно публикует `dist/latest.json`.
`dist/home-cinema.apk` остаётся адресом первого ручного обновления.
Нельзя повторно публиковать изменённый APK с тем же versionCode: каждый выпуск требует увеличения кода.

На домашний сервер (`192.168.1.144`) копируются только готовые APK и latest.json,
а для обновления backend — готовый Docker-образ, собранный и протестированный на Autobot.
Порядок публикации: неизменяемый APK, затем home-cinema.apk, последним latest.json
(все замены через временный файл и rename). Старые APK сохраняются для уже начатых загрузок.
Backend отдаёт `/api/v1/app-update`: versionCode, versionName, changes, apkUrl, size,
sha256, minSdk. При отсутствии или повреждении выпуска API отвечает 503 и ничего не предлагает.

Клиент проверяет обновления при старте и в «Настройки → Проверить обновления».
После «Обновить» проверяются размер, SHA-256, имя пакета, версия и существующая подпись.
APK загружается только с того же сервера, без переходов на другие адреса.
При необходимости Android открывает разрешение «Установка неизвестных приложений»
для Home Cinema; после возврата кнопкой Back запускается стандартное подтверждение установки.
Установка использует PackageInstaller в режиме обновления существующего пакета.
Приложение не удаляется, данные backend и SharedPreferences не очищаются.
Установка без подтверждения выключена; проверка на Xiaomi пока не проведена.

Для первого перехода с 0.9.7 установите подписанный 0.9.8 через `/install` **поверх**
текущего приложения. После этого последующие выпуски доступны из приложения.
При сбое сети загрузку можно повторить; частичный APK не устанавливается.
Ошибки подписи, нехватки места, несовместимости, блокировки и отмены показываются пользователю.
Возврат позиции просмотра по-прежнему требует кнопки Back во внешнем плеере.

Прогресс однозначно распознанной серии общий в рамках карточки сериала для всех качеств.
Неизвестные номера, сборники из нескольких серий и фрагменты остаются привязанными к файлу.
Существующие записи истории сохраняются, сопоставление добавляется при запуске backend.
Отметка «Просмотрено» выставляется после 90% видео длительностью от 10 минут или
явного завершения плеером. Длительность теперь передаётся и списку файлов для полосы прогресса.

На текущем домашнем сервере backend запускается готовым образом через override:
`docker compose -f compose.yaml -f compose.release.yaml up -d --no-deps --no-build --pull never backend`.
Это обновляет только backend и не запускает init, Jackett или TorrServer.
Откат backend: `docker compose -f compose.yaml up -d --no-deps --no-build --pull never backend`
(базовый compose на сервере сохранён с образом 0.9.7; миграция базы только добавляет таблицу).
Перед выпуском сохранена проверенная SQLite-копия на обоих серверах; старый APK и образ сохранены.

Справка Android для последующего исследования тихой установки:
https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int)
На Android 12+ API допускает обновление приложением самого себя без подтверждения при выполнении
условий платформы и с UPDATE_PACKAGES_WITHOUT_USER_ACTION. Конкретная версия/прошивка Xiaomi
не проверена: телевизор выключен. Текущий выпуск явно требует подтверждения Android и не
объявляет разрешение на установку без участия пользователя.

Спецвыпуски LostFilm без SxxExx объединяются с сериалом по точной ссылке источника.
Все качества остаются отдельными раздачами внутри карточки. Прежние ID карточек
разрешаются как ссылки на общий сериал; сохранённые раздачи, история и прогресс не
переписываются. Избранное прежних карточек учитывается при отображении общего сериала.
Совпадение названий без подтверждённой ссылки источника не является основанием для объединения.
